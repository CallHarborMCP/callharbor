# CallHarbor v1.0.0 — locked Definition of Done

Every item below is mandatory. An issue is done only when PR merged, required CI passed and evidence links exist. No skipped/flaky or suppressed checks to artificially pass, no fake completion based on mocked product behavior. Do not declare v1 release until all release issues under the v1.0.0 milestone are closed with evidence.

1. Full user/admin accounts + optional OIDC, multi-admin and correct per-user isolation on REST/MCP/GUI/recording bytes. Built-in OAuth2.1 MCP auth works with a real conforming remote client; ChatGPT-specific authentication flow is tested as far as test tooling permits, with unverified app UI claims labeled as such.
2. Two roles implemented server-side with full responsive React UI mobile/tablet/desktop, visually polished theme system configurable in GUI (light/dark/system, accents, presets, density), visual regressions and accessibility testing. ALL WebGUI-visible copy is English only in V1 across every screen, wizard, toast, error, setting, accessibility label and legal recording prompt. Voice call language is independently configurable and NOT restricted by GUI language.
3. Own Telnyx profiles, numbers, API secret protection, webhook signature validation, read-only connection validator and provider-protocol contract coverage.
4. Own OpenAI-compatible realtime endpoint/model/auth, speech-to-speech engine with bidirectional audio, barge-in (clear/truncate), DTMF where available, reliable hangups, session recovery and appropriate buffering. No additional paid AI provider.
5. MCP prep-driven autonomous calls with long context, constraints, fallbacks, immutable versioned task brief, tools, asynchronous status, idempotency and robust outcome reporting with evidence.
6. Complete audit: call timeline, reason codes, conversation transcript, per-user/overall diagnostics, accurate cost estimates vs confirmed amounts; no fabricated task success or audio transcripts.

On enabling, show an explicit warning/acknowledgement that the user must ensure any required notice or consent wording is supplied in the AI prompt; no automatic announcement or jurisdiction-specific compliance engine. `make_call(record=true)` cannot bypass a disabled owner recording preference. Browser-playable audio with seek, authorized download/range, partial-file signaling, configurable retention, backups/restores and encryption/key lifecycle tested. No paid recording add-on. Test default OFF, enable warning, persistence, disable and forbidden MCP override.

Repeatable automated CI: unit/integration/race/contract/auth/E2E/Playwright/visual/security/performance and full Docker end-to-end with independent Telnyx/media and realtime protocol harness; no live phone calls/AI API payment in CI. CI must measure and report actual performance, not promise a fixed amount.

Threat model, security review, code/license audit of reused patterns, dependency provenance; COMPLETE professional user/admin/operator/developer documentation (installation, configuration, OAuth/MCP, Telnyx, AI providers, data/retention, upgrades/rollback, backup/restore, troubleshooting, API, architecture, CI and licensing). Verify artifacts from a clean environment before completion marker PR.
12. Final `.autonomous/V1_COMPLETE` exists on protected clean main only after verified release, completed/issues closed and green CI. The runner must stop automatically; project remains supported by CI after release.

## Tendo V3-quality release requirements
- Implement two real interactive design concepts, capture authentic screenshots, review them critically and document the chosen direction and design system in `docs/design/`. Require real responsive production screenshot evidence and meaningful WCAG-oriented browser tests.
- Project-local pinned Go, Node/npm and Playwright versions and a unified local verification command must match the required CI versions. First PR introducing source/code must add corresponding real product tests in standard Go/Node/Playwright/Compose tooling; no skipped local-only tests.
- Independently audit maintainability, architectural boundaries, auth/tenant and audio correctness; fix identified release blockers before release instead of merely documenting them.

## Autonomous blocker recovery policy
A blocker is work for the autonomous agent, not a reason to declare success, terminate the runner, or solicit routine human development. When a required capability seems impossible, reproduce the failure, investigate docs/reference implementations/issues and alternative standards-compatible approaches, write tests, record an ADR, and keep iterating without reducing V1 scope or introducing paid services. Work on independent tasks while one dependency is blocked. When ALL open issues are externally blocked, periodically resume bounded autonomous unblock investigation with exponential backoff; leave the systemd service alive. For genuinely unavailable external access (missing credential/permission, service outage, unfixable upstream), record exact blocker and needed external action in GitHub; do not fabricate evidence, skip tests, fake the release, spin continuously, or mark a blocked issue complete. Resuming automatically after environment/issue changes is mandatory. No requirement for manual paid Telnyx call before release.
